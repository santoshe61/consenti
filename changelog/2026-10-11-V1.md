## [0.5.1] - 2026-10-11
### Summary
Three related changes to `compliance.type: 'auto'` geo-routing. (1) The United Kingdom never resolved: geo providers (`geoip`, `maxmind`), the built-in timezone table and `en-GB` language tags all emit ISO `GB`, while `EMBEDDED_COMPLIANCE_MAP` keys it as `UK`, so `GET /resolve-profile` returned `{ path: null, complianceGroup: 'opt-in', found: false }` and the widget showed the default banner even with an active `opt-in` profile (storage-independent). (2) `compliance.complianceMap` replaced the whole embedded map, so changing one country required re-declaring every country served; a new `override` key keeps the replace default (`true`) and lets `override: false` merge instead. (3) Custom `geoDataProvider` functions only saw `{ ip, language, timezone }`; they now get the full browser hints the widget already sends.
### Added
- `@consenti/utils`: `findCountryEntry()` — country lookup that treats `GB` and `UK` as the same country
- `@consenti/types`: `ComplianceMapData.override?: boolean`; `CountryResolverFn` context gains `languages: string[]` and `locale: string`; `WidgetCountryResolverFn` receives `{ timezone, language, languages, locale }`
- `@consenti/api`: `/resolve-profile` forwards the widget's full `languages` list and requested `locale` to `geoDataProvider` (also parsed from `Accept-Language` when the widget hints are absent); input is sanitised (max 20 languages, tags up to 35 chars)
- `@consenti/ui`: standalone-mode `geoDataProvider` is called with the browser hints
### Changed
- `@consenti/utils`: `resolveComplianceMapOverride()` merges an operator map over the embedded map when the document sets `override: false` (country-level replacement — an operator entry replaces the embedded entry wholesale, never deep-merged); `override: true`/omitted keeps the existing replace behaviour; a non-boolean `override` fails validation and falls back to the embedded map
- `@consenti/ui`: standalone-mode `complianceMap` honours `override: true` (an unlisted country gets the strictest group, `'opt-in'`, instead of falling back to the embedded mapping); omitted/`false` keeps the existing fall-back — the widget default intentionally differs from the server's
- `@consenti/api`: setup-wizard config summary states whether a custom map merges or replaces
### Fixed
- `@consenti/api`: `/resolve-profile` resolves `Europe/London` / `en-GB` / geoip `GB` visitors to the UK group (`opt-in`)
- `@consenti/ui`: standalone `compliance.type: 'auto'` resolves `en-GB` browsers
- `@consenti/ui`: `profile-resolver` integration test harness no longer throws on Node 21+ (`navigator` is getter-only)
### Breaking changes
None.
### Migration
None. To change only some countries, add `override: false` to your `complianceMap` document.
