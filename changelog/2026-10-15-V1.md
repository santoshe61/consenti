## [0.5.1] - 2026-10-15
### Summary
On Windows, saving or activating a profile failed with `EPERM: operation not permitted, rename '...\profiles\<tenant>\<group>.new-xxxxxxxx' -> '...\profiles\<tenant>\<group>'` (HTTP 500). The hot-serve directory for a compliance group is a junction, and Windows refuses to rename over an existing junction, whereas POSIX `rename()` atomically replaces a symlink. The version files were written but the live `{complianceGroup}/` path was never re-pointed, so the banner kept serving the old snapshot.
### Added
None.
### Changed
None.
### Fixed
- `@consenti/api`: activating a profile on Windows no longer fails with `EPERM` when the compliance-group junction already exists — the existing junction is removed just before the swap (the previous version's own directory is untouched). The swap stays a single atomic `rename()` on macOS/Linux. The temporary junction is now cleaned up if the swap fails.
- `@consenti/api`: the `json` storage adapter no longer breaks on Windows — it derived the parent directory with a `/`-only regex, so on a backslash path it created a *directory* named `consenti-data.json`; every write then failed (logged as a warning only) and the data was lost on restart. It now uses `path.dirname()`.
### Breaking changes
None.
### Migration
None. A profile whose activation failed earlier is repaired by saving it again.
